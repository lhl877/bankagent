# 部署说明

本文说明如何运行 bankagent，以及**为什么它不应该被暴露到公网**。

> 结论先行：这是一个**竞赛演示项目**。请只在本地或可信局域网内运行。
> 如果你需要对外演示，用录屏或截图，不要开公网端口。

---

## 1. 本地运行

### 环境要求

| 项 | 要求 |
|---|---|
| Python | **3.9+**（开发验证于 3.11.9） |
| 第三方依赖 | **无**。全部使用标准库（`sqlite3` / `http.server` / `hmac` / `hashlib` / `ast` / `unittest` 等） |
| 浏览器 | 任意现代浏览器（演示界面用原生 JS，无构建步骤） |

不需要虚拟环境，不需要 `pip install`。

### 启动

```bash
cd F:\dsh\work\bankagent
python api_server.py
```

启动后终端会打印访问地址：

```
  ┌────────────────────────────────────────────────────┐
  │  银行 AI 智能体 · 演示原型                          │
  │                                                    │
  │  http://127.0.0.1:8090/                            │
  │                                                    │
  │  权限分级：绿=自动 · 黄=确认 · 红=短信强验证         │
  │  Ctrl+C 停止                                       │
  └────────────────────────────────────────────────────┘
```

打开 **http://127.0.0.1:8090/**

### 命令行参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--port` | `8090` | 监听端口 |
| `--host` | `127.0.0.1` | 监听地址。只在本机访问用默认值 |
| `--keep` | 关闭 | 保留上次的数据库，不重置演示数据 |

### 生命周期说明

- **每次启动默认重置数据**：账户余额、订阅状态都回到种子值。
  演示时这是个优点（每场都从干净状态开始）。
  如果你想保留上次的操作结果，加 `--keep`。
- **重置不会删文件**：走的是清表（`reset_data()`），
  因为服务运行期间数据库文件是打开的，Windows 下删不掉。
  界面上右上角的 ⟳ 按钮也是调这个接口。
- **停止服务**：终端里按 `Ctrl+C`。如果直接关终端窗口或强杀进程，
  可能留下孤儿进程锁住 `demo_bank.db`（见第 5 节的故障处理）。

### 运行时产生的文件

| 文件 | 说明 | 是否入库 |
|---|---|---|
| `demo_bank.db`（+ `-wal` `-shm`） | 模拟银行数据库 | ✗ 已 gitignore |
| `audit.log` | 审计日志（哈希链） | ✗ 已 gitignore |
| `__pycache__/` | Python 字节码缓存 | ✗ 已 gitignore |

删掉这些文件不影响运行，下次启动会重新生成。

## 2. 局域网演示

如果评委或队友在另一台机器上，需要让他们访问你的界面：

```bash
python api_server.py --host 0.0.0.0 --port 8090
```

然后查明本机局域网 IP：

```powershell
# Windows
Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object { $_.IPAddress -notlike '127.*' -and $_.IPAddress -notlike '169.254.*' } |
  Select-Object IPAddress, InterfaceAlias
```

其他人访问 `http://<你的IP>:8090/`（例如 `http://10.40.36.72:8090/`）。

### 注意事项

**① 启动时打印的地址仍然是 `127.0.0.1`（已知缺陷）**

`api_server.py` 第 366 行的逻辑是：

```python
url = 'http://%s:%d/' % ('127.0.0.1' if args.host == '0.0.0.0' else args.host, args.port)
```

`--host 0.0.0.0` 时它把地址显示成 `127.0.0.1` —— 这个地址**别人访问不了**，
恰好在局域网场景下帮不上忙。请忽略这行提示，用上面查到的局域网 IP。

**② Windows 防火墙会拦**

第一次用 `0.0.0.0` 启动时 Windows 会弹网络访问提示，要选「允许」。
如果没有弹窗或误点了拒绝，手动加规则：

```powershell
New-NetFirewallRule -DisplayName "bankagent demo" -Direction Inbound `
  -Protocol TCP -LocalPort 8090 -Action Allow
```

用完建议删掉：

```powershell
Remove-NetFirewallRule -DisplayName "bankagent demo"
```

**③ 局域网内所有人的操作共享同一份数据**

服务端是单进程、内存里存会话，但**数据库是共享的**。
一个人在界面上转账，别人刷新就能看到余额变化。
演示时这通常没问题，但如果多人同时演示要注意会互相影响。

**④ 共用网络要小心**

在咖啡厅、酒店、展会这类共用 Wi-Fi 下开 `0.0.0.0`，
同网络的其他人都能访问到。没有身份认证，任何人都能操作演示账户。
建议只在可信网络下这么做。

## 3. 为什么不要暴露到公网

**这一节是重点。请认真读完再决定是否要把端口开到公网。**

系统当前**刻意省略了所有生产环境必需的安全措施**，因为这些不是赛题考察点，
而且加上去会让演示变复杂。具体来说：

### ① OTP 验证码明文回传（最严重）

红色级操作的短信验证码，接口会**直接把明文返回给前端**：

```
POST /api/verify/request
→ {"type":"otp_sent","challenge":"...","demo_code":"455423", ...}
                   ↑ 真实系统绝不可能这样
```

代码里也标注了：

> 真实系统只发短信，绝不回传验证码。演示环境回传是为了让评委能亲手跑通流程。

**公网暴露的后果**：任何人只要能调用这个接口，就能拿到验证码，
绕过"强验证"这道防线。红色级操作的多因子认证**完全失效**。

界面上也写明了这是演示行为（弹窗里那行小字），但界面的提示拦不住直接调接口的人。

### ② 没有任何身份认证

- 没有登录，没有会话令牌，没有用户概念
- `session` 是前端随机生成的字符串，服务端只当分组键用
- 任何人都能用任意 `session` 发请求
- `/api/state` 直接返回**全部 5 个账户**的余额、卡号、脱敏手机号

**公网暴露的后果**：任何人可以查询和操作任意账户。

### ③ 没有速率限制

- `/api/chat`、`/api/execute`、`/api/verify/request` 都可无限次调用
- 熔断（`CircuitBreaker`）是**按会话**的，换个 `session` 字符串就重置了
- OTP 有 5 次尝试上限，但可以无限次重新申请验证码 —— 等价于没有上限

**公网暴露的后果**：可以脚本化刷接口，DoS 掉服务，或者暴力枚举验证码。

### ④ 其他

| 项 | 现状 | 公网下的后果 |
|---|---|---|
| 传输加密 | 明文 HTTP | 中间人可读取和篡改全部流量 |
| 数据库 | SQLite 文件，无加密 | 拿到文件即拿到全部数据 |
| 密钥管理 | 无（无外部凭证） | — |
| 日志脱敏 | 部分脱敏（`_safe_params` 只处理账号前 3 位） | 日志仍含交易金额等 |
| 错误处理 | 返回通用错误，不回栈 | 尚可，但不是为对抗环境设计的 |
| CORS | 未设置限制 | 任意站点可发起请求 |

### 结论

**不要 `--host 0.0.0.0` 到公网。** 需要对外展示时：

- ✅ 录屏（赛题本来也要求 5 分钟演示视频）
- ✅ 截图（`shots/` 目录已有 7 张）
- ✅ 本地跑给评委看
- ✅ 可信局域网内演示
- ❌ 开公网端口 / 用内网穿透工具暴露

按**优先级**排列。前 4 项不做完，任何真实的资金操作都不能上线。

### P0 · 阻断性（不做就不能碰真钱）

| # | 要补什么 | 为什么 |
|---|---|---|
| 1 | **真实身份认证**：对接银行 SSO / OAuth2 / mTLS，建立用户与会话概念 | 当前任何人都能操作任意账户 |
| 2 | **OTP 走真实短信网关**，服务端只存哈希，绝不回传明文 | 当前强验证可被直接绕过 |

| 4 | **服务端权威权限判定**：把权限从"演示规则"换成行内风控策略，且必须有服务端强制 | 当前规则是我们自己定的 |

## 5. 故障处理

### 启动报错：`数据库文件被占用，无法删除`

**原因**：上一个服务进程没有正常退出，仍然持有 `demo_bank.db` 的文件句柄。
Windows 下文件被占用时无法删除，而启动流程默认要重置数据库。

**典型触发场景**：直接关掉终端窗口、用任务管理器强杀进程、
或者上一个进程是被 `Stop-Process` 之类的方式结束的（子进程可能变成孤儿）。

**处理**：

```powershell
# 1. 找出残留进程
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Select-Object ProcessId, CommandLine

# 2. 确认是 api_server.py 后杀掉
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -like '*api_server*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }

# 3. 清理残留的库文件（可选，删了会重新生成）
Remove-Item demo_bank.db* -Force -ErrorAction SilentlyContinue
```

**或者绕开**：用 `--keep` 启动。它会跳过重置步骤，因此不需要删文件：

```bash
python api_server.py --keep
```

实测确认这确实可行：在上一个实例仍持有数据库的情况下，
`--keep` 能正常启动并读写（返回 5 个账户、对账 `ok`），
因为 SQLite 的 WAL 模式支持多连接并发。

> ⚠️ **但这不是真正的修复，只是绕过。**
> `--keep` 之后两个进程在**共享同一个数据库**，
> 两边都能改余额，你会看到一个状态不确定的演示环境。
> 正确做法还是先杀掉残留进程，再用正常方式启动。
> `--keep` 只适合"我不想重置数据"这个正当用途。

### 端口被占用：不会有报错，会出现"幻影实例"

**这一点容易踩坑，实测结论如下。**

如果你重复启动同一个端口，**第二个实例不会报错**。它会正常打印启动横幅、
正常接受 `Ctrl+C`，看起来完全正常 —— 但实际上：

```
$ python api_server.py --port 8090 --keep     # A，正常服务
$ python api_server.py --port 8090 --keep     # B，也启动了，不报错
```

- 两个进程都绑定了 8090（实测：杀掉 A 之后 B 能立刻接手响应请求）
- `Get-NetTCPConnection -LocalPort 8090 -State Listen` **只会显示一个 PID**，
  所以用它排查会看到"只有一个进程"，从而误判
- 请求被 Windows 投递给其中一个，你无法控制是哪个
- **B 仍然持有 `demo_bank.db` 的文件句柄**

**根本原因**：`http.server.HTTPServer` 默认设置了 `allow_reuse_address = 1`，
在 Windows 上表现为 `SO_REUSEADDR` 允许同地址二次绑定。
（实测：两个 socket 都设 `SO_REUSEADDR` 时，二次 `bind` + `listen` 都成功。）

**危害**：真正的麻烦不是端口，而是**数据库文件被多进程持有**。
这就是下一节那个"数据库文件被占用"报错的来源 ——
你发现库里被锁，却用端口查不到是哪个进程，因为第二个实例在端口列表里不显示。

**排查**：按**命令行**找进程，不要按端口找。

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -like '*api_server*' } |
  Select-Object ProcessId, CreationDate, CommandLine
```

看到多个就全部杀掉，然后清理库文件：

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -like '*api_server*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
Remove-Item demo_bank.db* -Force -ErrorAction SilentlyContinue
```

**想换端口就用不同的 `--port`**，不要在同端口上重复启动。

> 已知缺陷：程序启动时没有做"端口已被占用"的检测。
> 正常做法是绑定前先探测，或者依赖 `bind()` 抛错 ——
> 但 `allow_reuse_address` 把那个错也吞掉了。
> 修法是把 `allow_reuse_address` 设为 `False`
> （或在 Windows 上改用 `SO_EXCLUSIVEADDRUSE`）。当前未修。

### 界面打不开但终端显示已启动

1. 确认地址是 `http://127.0.0.1:8090/`（注意是 `http` 不是 `https`）
2. 确认端口没被改（看终端打印的地址）
3. 如果用了 `--host 0.0.0.0`，用局域网 IP 而不是 `127.0.0.1` 从别的机器访问
4. 检查防火墙

### 重置演示数据

界面上右上角的 ⟳ 按钮，或调接口：

```bash
curl -X POST http://127.0.0.1:8090/api/reset -H "Content-Type: application/json" -d "{}"
```
