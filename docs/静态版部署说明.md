# 部署说明（静态演示版）

线上地址：https://bankagent.pages.dev

## 为什么是静态版

Agent 的逻辑在 Python 后端（api_server.py + agent/ + security/），
Cloudflare Pages 只能托管静态文件，**跑不了 Python 进程**。

所以线上站点是 `public/` 目录里的静态版：
  index.html + app.css + app.js + mock-api.js

`mock-api.js` 把后端的**真实输出**预置成静态响应 —— 金额、判定依据、
审计事件名都取自 `python api_server.py` 的实测结果，
分级判定与金额抽取则在前端按相同规则重算。
区别只在于：静态版不会真正持久化数据，也不是服务端算的分级。

**完整版（Python 后端）**：`python api_server.py` → http://127.0.0.1:8090/

## 重新部署

    wrangler pages deploy public --project-name=bankagent --commit-dirty=true

注意：项目的**生产分支是 master**。如果本地分支不是 master，
部署会落到 Preview 环境，生产域名不会更新（这个坑踩过一次）。

## 两个项目的关系

| 目录 | 用途 | 部署 |
|---|---|---|
| `public/` | 静态演示版 | Cloudflare Pages（bankagent.pages.dev） |
| `web/` | 完整版前端，调 Python 后端 | 本地运行 |

两边的 `index.html` / `app.css` 内容一致，`app.js` 差一处：
静态版的 `api()` 优先走 `window.__API__`（由 mock-api.js 提供），
因为 `app.js` 是 defer + 同步执行，会捕获 `fetch` 的原始引用，
单纯覆写 `window.fetch` 对它无效。
