## 版本一（中文字 165 · 含标点 199）

金盾是一个"说话就能办业务"的银行智能体：用户用自然语言完成转账、账单分析、订阅与卡片管理，Agent 自主识别意图、规划任务，并在严格的权限框架内执行。

核心主张：模型可以表达意图，但不能给自己发权限。分级由代码判定而非模型决定，自然语言只进解析器，注入无法提权；确认凭证绑定操作内容，改参数即失效；执前重算风险等级。

另有受限 AST 沙箱、哈希链审计与异常熔断。86 个测试全绿，19 项越权排查全部拦住。

## 版本三（中文字 418 · 含标点 497）

手机银行的痛点是路径长、入口深 —— 转一笔账平均要 3 步以上。但把大模型直接接进银行，会带来一个更严重的问题：聊天助手说错了，用户重问一遍即可；银行 Agent 说错了，**钱已经出去了**。幻觉在聊天里是体验问题，在银行是资产与合规事故。

本项目构建一个"说话就能办业务"的银行智能体，用户用自然语言完成转账、账单分析、订阅管理、卡片操作。核心主张是：**模型可以表达意图，但不能给自己发权限。**

我们建立三级权限体系：绿色纯查询自动执行；黄色小额转账（单笔与日累计均 ≤ 1000 元）需用户确认；红色大额转账、挂失、申购等需短信验证码强验证。资金变动只允许经过唯一入口且必须携带幂等键，重复提交不会重复扣款。每次执行前重新判定风险等级，确认凭证绑定操作内容哈希，篡改金额立即失效。

安全边界全部是结构性的，不依赖提示词：自然语言只进入意图解析器，产出结构化参数后即退出流程；风险分级函数不读用户原文；受限 AST 白名单沙箱；哈希链防篡改审计；异常熔断。

四个核心模块自测全部通过，86 个测试用例全绿，19 项授权与凭证缺陷排查全部拦住。可现场演示"注入攻击被拒绝""拆分转账绕不过强验证""错误验证码无法执行"。
